# MaixCAM2 A版实机故障调试手册增补设计

## 目标

在现有`maixcam2_app_A_quad/A版实机调试手册.md`中增加可按现场现象直接执行的故障调试流程，并重点解释KNOWN保存后下半区没有目标轮廓的问题。

## 已确认行为

| 行为 | 程序实际含义 |
|---|---|
| 正常界面`N=4` | 画面中有4个`complete=True`的完整轮廓，不区分上半区、下半区或跨线 |
| `SAVE` | 仅在KNOWN模式登记红线下方的四片正确100×60mm布局，并重置旧规划 |
| KNOWN规划输入 | 只接受`complete=True`且`region=upper`的碎片，必须恰好4片 |
| `PLAN KNOWN_NEEDS_FOUR` | 进入KNOWN求解的上半区有效碎片不足4片，或模板数量不足4个 |
| 下半区目标绘制 | 只有规划成功并显示`PLAN OK N=4`后才绘制目标外框、单片轮廓、箭头和位姿 |

## 文档结构

1. 在KNOWN章节增加“保存与规划是两个阶段”的流程图式步骤。
2. 增加截图状态`N=4 + PLAN KNOWN_NEEDS_FOUR`的专项排查说明。
3. 增加完整故障决策流程，按ROI、MASK、RESULT、ADV、KNOWN、UNKNOWN和目标绘制分层定位。
4. 扩充状态表，加入KNOWN与UNKNOWN规划失败状态、判断依据和最小修正动作。
5. 明确当前A版在相机画面下半区直接叠加目标，不提供独立黑底拼装示意窗口。

## 调试原则

- 先读屏幕完整状态，再决定进入哪个页面。
- MASK不正确时不先修改面积阈值。
- 每次只改变一个参数，并记录修改前后的状态。
- 识别、区域分类、模板登记、规划求解和目标绘制分层判断，不把`N=4`误认为规划条件已经满足。

## 验收标准

- 手册能够直接回答“为什么保存后下半区没有目标”。
- 手册包含`PLAN KNOWN_NEEDS_FOUR`的原因和操作步骤。
- 手册覆盖AUTO ROI、粘连、漏检、噪声、EDGE、SMALL、LARGE、KNOWN和UNKNOWN常见失败。
- 所有界面文字、参数和持久化行为与A版v1.2.0代码一致。
