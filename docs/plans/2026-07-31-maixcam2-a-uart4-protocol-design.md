# MaixCAM2 A版 UART4 二进制通信设计

## 1. 目标与边界

本功能只修改 `maixcam2_app_A_quad`，保留现有三片识别、KNOWN/UNKNOWN 求解和单次快照逻辑，不合并其他分支的求解算法。

MaixCAM2 通过 UART4 向 STM32F4 发送三类信息：

1. 周期心跳，用于判断双向链路是否连通。
2. 调参 ROI 页手动触发的完整 A4 四角毫米坐标。
3. 拼图求解成功后一次性发送全部碎片的移动前中心、目标中心和旋转角。

本轮只实现 MaixCAM2 端。STM32F4 端不创建源码，在 A 版目录提供独立协议说明文档，明确接收状态机、CRC、ACK、去重和字段解析方法。

## 2. 坐标约定

- 所有发送坐标均使用完整 A4 纸面坐标，不发送相机像素。
- 原点为完整 A4 左上角，X 轴向右，Y 轴向下。
- 竖放纸面范围为 `210 x 297 mm`；横放纸面范围为 `297 x 210 mm`。
- A4 四角顺序固定为左上、右上、右下、左下。
- 拼图结果中的源中心是碎片移动前中心，目标中心是拼装完成后该碎片应到达的中心。
- 旋转角表示源姿态到目标姿态的增量，从纸面上方观察，正值顺时针、负值逆时针，范围为 `[-180, 180)`。
- 毫米和角度均乘以 10 编码为定点整数，协议单位分别为 `0.1 mm` 和 `0.1 deg`。

## 3. UART4 接口

| 项目 | 配置 |
|---|---|
| MaixCAM2 TX | `A21 / UART4_TX` |
| MaixCAM2 RX | `A22 / UART4_RX` |
| Linux 设备 | `/dev/ttyS4` |
| 波特率 | `115200` |
| 数据格式 | `8N1`，无流控 |

MaixPy 使用官方 `maix.uart`、`maix.pinmap` 和 `maix.comm` API。应用打开UART4前显式调用`comm.rm_default_comm_listener()`停止默认Maix Comm监听，再映射引脚并构造UART对象；打开失败或包装UART关闭时调用`comm.add_default_comm_listener()`归还默认监听。应用运行期间UART4由本协议独占，不能依赖UART构造函数隐式释放系统监听。

## 4. 通用帧格式

所有多字节整数均为小端序，不允许直接发送 Python 浮点数或依赖 C 结构体内存布局。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | SOF | 固定 `0xAA 0x55` |
| 2 | 1 | VERSION | 固定 `0x02`；版本2引入10字节会话心跳，不兼容旧版6字节心跳 |
| 3 | 1 | TYPE | 消息类型 |
| 4 | 1 | FLAGS | bit0=`ACK_REQUIRED`，bit1=`RETRY` |
| 5 | 2 | SEQ | `uint16` 序号，循环递增 |
| 7 | 2 | LENGTH | `uint16` 载荷字节数 |
| 9 | N | PAYLOAD | 类型相关载荷 |
| 9+N | 2 | CRC16 | CRC16-CCITT-FALSE，小端 |

CRC 参数固定为：多项式 `0x1021`、初值 `0xFFFF`、不反射、结果异或 `0x0000`。计算范围从 `VERSION` 开始，到 `PAYLOAD` 最后一个字节结束，不包含 SOF 和 CRC 字段。标准校验向量 `"123456789"` 的结果必须为 `0x29B1`。

接收解析器必须支持串口断包、粘包、帧头前噪声、非法长度和 CRC 错误。最大载荷限制为 64 字节；错误帧不得影响后续合法帧重新同步。

## 5. 消息定义

| 名称 | TYPE | 方向 | 是否要求 ACK |
|---|---:|---|---|
| `HEARTBEAT` | `0x01` | MaixCAM2 -> F4 | 是 |
| `PAPER_FRAME` | `0x10` | MaixCAM2 -> F4 | 是 |
| `PUZZLE_RESULT` | `0x20` | MaixCAM2 -> F4 | 是 |
| `ACK` | `0x80` | F4 -> MaixCAM2 | 否 |

### 5.1 HEARTBEAT

| 载荷偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | `uint32` | `session_id` | 每次视觉应用启动生成的随机非零会话ID |
| 4 | `uint32` | `uptime_ms` | 本次视觉应用运行毫秒数，允许回绕 |
| 8 | `uint8` | `app_state` | 0待机、1调参、2采集、3求解、4结果就绪 |
| 9 | `uint8` | `last_error` | 0表示无通信错误，其他值保留 |

每 500 ms 发送一帧。同一轮`poll()`先写HEARTBEAT，再写已排队的业务帧。MaixCAM2在1500ms内收到任何CRC正确且字段匹配的ACK即显示`UART:OK`，否则显示`UART:OFFLINE`。心跳收发不得阻塞相机、触摸和增量求解主循环。

F4在接收首个合法10字节心跳前不得提交PAPER_FRAME或PUZZLE_RESULT。`session_id`变化表示视觉程序已重启，F4必须清空旧会话的`(TYPE, SEQ)`去重记录并作废未执行旧方案，再接受新会话业务；这样SEQ从0重新开始也不会与旧缓存冲突。

### 5.2 PAPER_FRAME

| 载荷偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | `uint8` | `orientation` | 0竖放，1横放 |
| 1 | `uint8` | `corner_count` | 固定为4 |
| 2 | `uint16` | `paper_width_x10` | 完整纸宽，单位0.1mm |
| 4 | `uint16` | `paper_height_x10` | 完整纸高，单位0.1mm |
| 6 | 16字节 | `corners_x10[4][2]` | 左上、右上、右下、左下，均为 `uint16` |

竖放发送 `(0,0)、(210,0)、(210,297)、(0,297) mm`；横放发送 `(0,0)、(297,0)、(297,210)、(0,210) mm`。

ROI 调参页增加 `SEND A4` 按钮。当前会话存在合法 `paper_quad` 时按钮启用；点击后发送当前横竖方向对应的完整 A4 毫米帧。发送、ACK 和失败状态显示在调参状态栏中，但不得自动保存或修改 ROI 参数。

### 5.3 PUZZLE_RESULT

载荷头：

| 载荷偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | `uint8` | `mode` | 0=KNOWN，1=UNKNOWN |
| 1 | `uint8` | `orientation` | 0竖放，1横放 |
| 2 | `uint8` | `piece_count` | 1至4 |
| 3 | `uint8` | `reserved` | 固定0 |

每条碎片记录固定 11 字节，紧接载荷头连续排列：

| 记录偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | `uint8` | `piece_index` | 从1开始的确定性序号 |
| 1 | `int16` | `source_x_x10` | 移动前中心X |
| 3 | `int16` | `source_y_x10` | 移动前中心Y |
| 5 | `int16` | `target_x_x10` | 目标中心X |
| 7 | `int16` | `target_y_x10` | 目标中心Y |
| 9 | `int16` | `rotation_deg_x10` | 旋转增量 |

总载荷长度必须满足 `4 + piece_count * 11`。所有碎片在同一个 `PUZZLE_RESULT` 帧内发送，不逐片拆帧。

只有新的 START 采集会话首次得到成功 `AssemblyPlan` 时才创建结果序号并发送。屏幕后续重复绘制同一个规划不能创建新序号。模式切换、重新 START 或进入 CAL 会结束旧结果发送上下文。

## 6. ACK、重发与去重

ACK 载荷固定为4字节：

| 载荷偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `uint8` | `acked_type` |
| 1 | `uint16` | `acked_seq` |
| 3 | `uint8` | `status`，0表示成功 |

MaixCAM2 对 `PAPER_FRAME` 和 `PUZZLE_RESULT` 保存原始逻辑消息。在未收到匹配 ACK 时使用相同 TYPE 和 SEQ 重发，并设置 `RETRY` 标志。首次三次重发间隔为 250 ms；仍未确认时降为每 1000 ms 重发，直到收到 ACK、产生新结果或用户切换采集上下文。

F4必须在当前`session_id`范围内使用`(TYPE, SEQ)`去重：重复帧只重发ACK，不得再次执行机械动作。首个合法心跳前业务帧不得执行；CRC错误、长度错误、版本错误或字段范围错误的帧不得执行。

## 7. 视觉端模块边界

新增独立纯 Python 协议模块，负责：

- CRC16计算、通用帧编码和流式解析。
- A4帧、结果帧和ACK载荷的定点编码/解码。
- UART4初始化、非阻塞轮询、心跳、在线状态、可靠消息重发和结果去重触发。

协议编码和状态机不得依赖 OpenCV 或 Maix 硬件对象，以便在 PC 上进行完整单元测试。Maix UART 对象通过小型适配器注入，PC测试使用内存串口替身。

`main.py` 只负责把当前界面状态、横竖方向、成功规划和按钮动作交给通信运行器，不在主循环内拼接二进制字段。

## 8. 调参界面与完整A4区域

CAL 底部布局扩展为六个稳定触摸槽。ROI/MASK/RESULT页面显示：

`AUTO ROI | - | 当前参数 | + | LOCK ROI | SEND A4`

ADV 页面继续使用原五个动作，第六槽禁用并留空，按钮坐标不随页面切换。

AUTO ROI 成功后允许黄色工作区域覆盖完整 A4，软件校验不再施加 230 mm 宽高上限。默认全纸参数为：

- 竖放：`X=0、Y=0、W=210、H=297、SPLIT=148.5、INSET=0`。
- 横放：`X=0、Y=0、W=297、H=210、SPLIT=105、INSET=0`。

设置校验仍要求黄色区域完整位于纸面内、宽高为正、分界线位于区域内部。机械实际可达性不属于视觉软件校验范围。

## 9. 故障处理

- UART4打开失败不能终止相机应用，界面显示 `UART:ERROR`，通信运行器按固定间隔重试初始化。
- `write()` 返回负数或短写视为发送失败，不把该帧标记为已发送成功。
- 无纸张标定时 `SEND A4` 禁用，不构造调试帧。
- 规划失败、坐标非有限数、碎片数不在1至4或定点数溢出时不得发送结果，并显示明确通信错误状态。
- 接收缓冲区超过上限时保留可能的帧头尾部并丢弃旧噪声，防止长期增长。
- 通信故障不得清除视觉规划、模板或已保存ROI。

## 10. 验证范围

PC自动测试必须覆盖：

- CRC标准向量、各消息逐字节黄金数据、负数角度和序号回绕。
- 流式解析的单字节断包、多帧粘包、噪声、非法长度和CRC错误恢复。
- 10字节心跳黄金数据、非零会话ID、0～4状态、心跳先于业务帧、在线/离线切换、ACK匹配、重发标志和结果只创建一次。
- UART4打开前停止默认监听、打开失败恢复监听、关闭租约恢复监听。
- 1至4片结果帧及KNOWN/UNKNOWN模式。
- ROI页六槽触摸命中、SEND按钮启用条件和其他页面禁用条件。
- 横竖完整A4黄色区域、分界线和设置持久化。
- 原有三片识别、求解、KNOWN保存、调参和显示回归测试全部继续通过。

PC无法证明UART4电气连接、MaixCAM2系统版本API兼容、STM32实际ACK时序和电机动作。发布后必须进行MaixCAM2与F4交叉接线、共地、逻辑分析仪帧检查和实机ACK/重发验证。
