# MaixCAM2 A版UNKNOWN WHITE四片快速求解设计

## 目标

针对实机四片日志中`GRAPH`无法表达分段接缝、`FALLBACK`在20秒墙钟内只推进85个节点的问题，增加一条仅用于UNKNOWN WHITE四片输入的快速路径。该路径必须支持整边和T形分段接缝，降低每个候选的重叠检查成本，并在无解时完整保留现有兜底搜索。

## 根因证据

使用现场日志中的四组毫米顶点离线复现，得到以下结果：

| 检查 | 结果 | 结论 |
|---|---:|---|
| GRAPH扩大到全部1016组连接关系 | 无解 | 增大32/90上限不能解决分段接缝问题 |
| 现有FALLBACK | 第168节点成功 | 轮廓与毫米坐标本身可解 |
| 成功布局 | 填充95.6%、重叠1.5%、四片均有外边 | 92%/3%验收阈值不是失败原因 |
| MaixCAM2超时状态 | 85节点、活动3319ms、墙钟20534ms | 正确分支尚未到达，且求解器只获得约16%的墙钟时间 |
| Beam宽度96/192/384 | 均在第168节点首解 | 继续增大现有局部前沿没有收益 |

正确布局包含短边贴合长边局部区间的T形接缝。现有GRAPH只枚举整边相近关系，无法生成该布局；现有FALLBACK虽然支持分段接缝，但采用逐父状态深度优先展开，并为大量错误候选重复创建栅格MASK。

## 已确认方案

求解顺序调整为：

```text
WHITE锁定1～4片快照
    -> 现有GRAPH整边快路径
    -> 恰好4片时执行FOUR_FAST分层Beam
    -> FOUR_FAST无解时进入现有FALLBACK
    -> 严格/容错硬验收
    -> 缓存成功或失败结果
```

不删除GRAPH，因为两片、三片和整边四片仍可由它快速完成；不替换FALLBACK，因为特殊凹多边形或分层Beam截断真实状态时仍需要完整兜底。

## FOUR_FAST分层Beam

FOUR_FAST复用`_build_edge_compatibility_graph()`生成的有向整边与`segmented`分段边关系，不再另建只支持整边的候选集。

主要流程：

1. 固定第0片局部位姿，消除整个拼图的平移与旋转自由度。
2. 第2层枚举任意剩余片与第0片的兼容接缝，生成全部合法两片状态。
3. 对同一“已放置碎片集合+量化位姿”去重，并按外框紧凑度、整边优先、接缝误差排序，全局保留有限宽度。
4. 第3层从所有保留的两片状态统一扩展，不再对单个父状态递归到底；再次全局排序和截断。
5. 第4层生成完整候选，先进行快速重叠剪枝，再调用现有92%严格验收；WHITE严格无解时才进入86%容错验收。
6. 第一个严格合格矩形立即返回；容错候选保留同层最低分结果。

该设计不是固定“2+2”拼接，因此不会漏掉一个碎片同时连接另外三片的星形拓扑。每层全局Beam可避免当前深度优先在某个错误两片状态下生成大量三片和四片组合。

## 快速重叠判断

中间状态采用三级判断：

1. 轴对齐外框没有内部交集时，立即判定不重叠。
2. 两个多边形均为凸多边形时，使用`cv2.intersectConvexConvex`计算真实交叠面积；共享边产生的零面积接触允许通过。求解开始时预先计算最终全部碎片面积，中间门用该总面积减去当前累计交叠估算最终联合面积，不能使用候选单片或当前已放片面积作分母。
3. 简单凹多边形使用耳切法分解为三角形，再累计三角形交集面积；自交、严重共线或OpenCV几何结果无效时才回退现有腐蚀后栅格MASK判断。

最终四片矩形仍调用现有`_canonicalize_complete_layout()`，继续使用2像素/mm栅格计算填充率与总重叠率。快速判断只用于搜索剪枝，不改变最终机械安全门。

## 求解调度

锁定第三个稳定帧后，视觉轮廓已经不会再变化。求解期间继续使用锁定检测结果，不重复运行阈值分割。v1.9.1把GRAPH、FOUR_FAST和FALLBACK合并进同一个`UnknownSolveJob`生成器：每检查一组GRAPH布局、一个FOUR_FAST对齐候选或一个FALLBACK候选就可让出，三阶段从锁定时刻开始共享24ms/64工作单元的单帧调度，以及8秒活动预算和30秒墙钟。这样快路径不会再绕过主循环预算。

本轮优先调整`AssemblyRuntime`的求解时间片，不直接停止相机驱动读取，避免MaixPy摄像头缓冲、图像引用生命周期和恢复重拍出现设备相关风险。若新的四片快路径在实机仍因相机读取占用过高，再单独设计冻结相机帧的第二阶段优化。

## 现场调试常量

在`assembly_planner.py`顶部集中增加或保留：

| 常量 | 默认值 | 作用 |
|---|---:|---|
| `UNKNOWN_FOUR_FAST_ENABLED` | `True` | 一键关闭四片快路径以回退旧版本行为 |
| `UNKNOWN_FOUR_FAST_BEAM_WIDTH` | `32` | 每一层全局最多保留状态数 |
| `UNKNOWN_FOUR_FAST_RELATION_LIMIT` | `6` | 每个有向片对最多展开的排序靠前关系数 |
| `UNKNOWN_FOUR_FAST_MAX_WORK_UNITS` | `2400` | 候选检查硬上限；中间层触顶转FALLBACK，完整层触顶仍验收已生成候选 |
| `UNKNOWN_SOLVER_ACTIVE_TIMEOUT_SECONDS` | `8.0` | 累计实际计算时间保护 |
| `UNKNOWN_SOLVER_WALL_TIMEOUT_SECONDS` | `30.0` | 总墙钟保护 |

Beam宽度和工作单元上限只影响速度与召回，不放宽尺寸、填充或重叠安全门。

## 诊断输出

调试开启时增加一条终态日志：

```text
[SOLVER] FOUR_FAST result=OK pairs=... triples=... complete=... dedupe=... overlap=... units=... elapsed_ms=...
```

`parents`记录实际开始展开的三层父状态数，`limit`记录是否触及工作量上限。完整层`limit=1`仍可能从已生成候选返回成功；中间层触顶或完整候选无解时，`result=FAIL`后继续打印现有FALLBACK日志。关闭`UNKNOWN_SOLVER_DEBUG`后不构造诊断字符串。

## 测试范围

1. 使用现场四片日志原始毫米顶点，FOUR_FAST必须返回成功，填充率不低于92%、重叠率不高于3%、四片均生成目标位姿。
2. 测试必须验证真实布局包含分段边，防止实现退化成GRAPH整边枚举。
3. 分层快路径的首解工作量必须显著低于旧FALLBACK现场路径，不以PC毫秒数作为唯一断言。
4. 凸多边形共享边不算重叠、实体相交会拒绝；简单凹多边形走三角化几何求交，异常轮廓继续回退栅格。
5. FOUR_FAST关闭、非WHITE、1～3片输入均保持旧路径。
6. 快路径无解时必须在同一个`UnknownSolveJob`中继续FALLBACK，不能直接返回失败或重建计时预算。
7. 现有92%严格、86%容错、3%重叠、尺寸范围和外边约束全部保持。
8. A版全量、编译、平铺发布包以及B版固定哈希边界通过。
