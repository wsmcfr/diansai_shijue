# MaixCAM2 拼图碎片识别设计

## 1. 目标与范围

第一版程序运行在 MaixCAM2 上，使用固定摄像头识别黑色 A4 纸上的白色拼图碎片。程序通过触摸屏切换“已知碎片”和“未知碎片”两种模式，并实时显示识别结果。

本阶段只完成碎片检测、几何信息提取、已知模板匹配和屏幕交互，不实现拼图求解、龙门架遮挡消除、机械运动控制及像素到机械坐标的完整标定。

## 2. 已确认约束

| 项目 | 约束 |
|---|---|
| 视觉平台 | MaixCAM2，使用 MaixPy 和 OpenCV |
| 摄像头 | 固定安装 |
| 背景 | 黑色纵向 A4 纸 |
| 碎片表面 | 白色纸片，后续可能包含扑克牌图案 |
| 碎片数量 | 1 至 4 片 |
| 碎片边数 | 每片不超过 5 条主要边 |
| 最短边长 | 不小于 20mm |
| 机械行程 | X/Y 方向 230mm×230mm，Z 方向 100mm |
| 有效视觉区域 | A4 中部约 210mm×230mm，上下各忽略约 33mm |
| 输入状态 | 启动识别时碎片随机摆放、互不重叠 |

## 3. 方案选择

采用 OpenCV 的灰度阈值分割和多边形轮廓拟合，不使用 YOLO 等需要训练数据的模型。

选择该方案的原因：

1. 黑色背景和白色碎片具有明显亮度差，传统阈值分割稳定且易于现场调整。
2. 拼图后续需要的是顶点、边长、中心和角度，轮廓算法可以直接提供这些几何数据。
3. 未知碎片没有固定类别，目标检测模型不能自然解决任意新形状识别问题。
4. MaixCAM2 官方 MaixPy 环境支持 `maix.camera`、`maix.touchscreen` 和 `cv2`。

## 5. 图像处理流程

### 5.1 图像采集

摄像头使用 BGR 格式采集，第一版分辨率为 640×480。启动后跳过若干帧，避免曝光和白平衡尚未稳定时产生错误结果。

### 5.2 工作区限制

程序通过可配置矩形限定有效工作区，只在 A4 中部约 210mm×230mm 范围内寻找碎片。第一版使用像素矩形配置，后续完成透视标定后再转换为毫米坐标区域。

### 5.3 前景分割

1. 将 BGR 图像转换为灰度图。
2. 使用高斯滤波降低纸面纹理和传感器噪声。
3. 优先使用 Otsu 自动阈值分离黑色背景与白色碎片。
4. 使用小尺寸开运算去除白色噪点。
5. 使用小尺寸闭运算填补白纸内部的小孔洞，但不得大到连接相邻碎片。

阈值、核尺寸和最小面积均集中存放在配置结构中，方便现场通过实拍图调整。

### 5.4 轮廓与多边形

使用 `cv2.findContours(..., cv2.RETR_EXTERNAL, ...)` 只提取最外层碎片轮廓。根据面积、边界接触情况和轮廓完整度排除纸屑、反光点及工作区边缘干扰。

使用 `cv2.approxPolyDP` 将轮廓拟合为主要多边形。拟合误差按轮廓周长比例计算，并在小范围内搜索，使主要顶点数量稳定在 3 至 5 个。每片碎片输出：

- 轮廓面积与周长；
- 多边形顶点列表；
- 几何中心与可吸取候选点；
- 最小外接矩形及方向角；
- 归一化边长序列；
- 内角序列；
- Hu 矩形状描述子。

## 6. 双模式设计

### 6.1 已知碎片模式

已知模式加载四个预存模板。模板保存归一化边长、内角、Hu 矩以及面积比例，不依赖碎片在画面中的平移和旋转。

匹配时综合以下分数：

1. Hu 矩距离；
2. 循环对齐后的边长序列误差；
3. 循环对齐后的内角序列误差；
4. 顶点数量是否一致。

四片碎片进行一对一全局匹配，避免两个观测轮廓同时被判为同一个模板。输出编号 `K1` 至 `K4`、匹配分数、中心和角度。

### 6.2 未知碎片模式

未知模式不尝试分类。检测到的轮廓按“从上到下、从左到右”的稳定顺序编号为 `U1` 至 `U4`，并输出完整几何信息，作为后续未知拼图求解器的输入。

## 7. 屏幕交互

使用 `maix.touchscreen.TouchScreen.read()` 读取触摸状态，并在松开时产生一次点击事件，避免长按连续切换。

界面顶部放置“已知”和“未知”两个模式分段按键，当前模式使用不同颜色高亮。画面叠加内容包括：

- 绿色碎片轮廓；
- 红色多边形顶点；
- 黄色中心十字；
- 碎片编号、顶点数和角度；
- 当前模式和有效碎片数量。

显示图像与物理屏幕尺寸不一致时，触摸区域使用官方 `image.resize_map_pos` 或等价比例映射处理。

## 8. 异常与边界处理

| 情况 | 处理方式 |
|---|---|
| 未检测到碎片 | 显示数量为 0，不输出历史结果 |
| 检测超过 4 个轮廓 | 仅保留面积最大的 4 个，并显示干扰提示 |
| 碎片接触或重叠 | 标记轮廓异常，不强行拆分；题目输入要求本身为互不重叠 |
| 轮廓接触工作区边界 | 标记为不完整轮廓，不进入模板匹配 |
| 已知模板匹配分数过低 | 显示 `UNKNOWN`，避免错误编号 |
| 反光导致轮廓抖动 | 使用多帧稳定判定，连续若干帧一致后才更新稳定结果 |
| 龙门架进入画面 | 第一版不专门处理，后续通过停车位和遮挡掩膜解决 |

## 9. 测试设计

### 9.1 PC 端算法测试

使用 OpenCV 对保存的实拍图运行核心算法，验证：

1. 1 至 4 片分离碎片能被正确计数；
2. 每片主要顶点数为 3 至 5；
3. 同一碎片旋转和平移后，已知模板编号保持不变；
4. 小噪点和背景纹理不会被识别为碎片；
5. 碎片接触工作区边界时能被标记为不完整。

### 9.2 MaixCAM2 实机测试

1. 验证摄像头采集、OpenCV转换和屏幕显示正常；
2. 验证触摸按键只在松开时切换一次模式；
3. 验证两种模式切换不会残留上一模式结果；
4. 在正常室内照明和不同旋转角度下测试识别稳定性；
5. 记录每帧处理耗时，保证交互显示流畅。

## 10. 第一版验收标准

1. 程序可以在 MaixCAM2 MaixPy 环境启动并持续显示摄像头画面。
2. 屏幕可在已知和未知模式之间可靠切换。
3. 黑色背景上互不接触的 1 至 4 片白色碎片能够被框出并编号。
4. 每片碎片能输出中心、方向角、面积和 3 至 5 个主要顶点。
5. 已知模式具备模板数据接口和一对一匹配逻辑。
6. 未知模式能稳定输出全部碎片的几何描述。
