# MaixCAM2 A版跨帧实时拼装求解设计

## 1. 目标与边界

本次只修改 `maixcam2_app_A_quad/`，修复UNKNOWN稳定3帧后和KNOWN点击SAVE后画面、触摸一起冻结的问题。稳定版 `maixcam2_app/` 与B版 `maixcam2_app_B_warp/` 不修改；碎片识别、A4四角标定、机械区域和拼装几何验收规则保持不变。

| 项目 | 设计约束 |
|---|---|
| 主循环 | 每一帧必须回到显示与触摸处理，禁止一次同步搜索独占数秒 |
| UNKNOWN | 稳定3帧后启动跨帧任务，完成前显示 `SOLVING` |
| KNOWN SAVE | 按键只启动登记任务，求解成功后才原子保存模板 |
| 搜索质量 | 找到首个合法矩形后保留一段有限纹理优化窗口，不再跑满12000节点 |
| 失败处理 | 无解、超限、文件写入失败均转成屏幕状态，不能退出或冻结主循环 |

## 2. 根因与控制策略

现有 `solve_unknown_layout()` 是递归同步函数。检测到牌面纹理后，白片首解早停失效，即使几十个节点内已经得到合法矩形，仍会为优化接缝纹理跑满12000节点。PC实测同一复杂四片输入需12～14秒，MaixCAM2上耗时更长。

修复采用协作式增量计算，不使用后台线程。搜索器在候选重叠、候选排序和完整布局验收之间设置可恢复让出点；主循环每帧最多推进一个短时间片和有限工作单元，随后立即继续绘制与触摸。线程方案不采用，因为MaixPy/OpenCV对象的线程安全和额外栈内存没有实机证据。

## 3. 求解任务接口

`assembly_planner.py`新增增量任务对象，内部持有生成器、搜索状态、结果和诊断数据。

| 接口/状态 | 含义 |
|---|---|
| `advance(time_budget_ms, work_unit_limit)` | 推进当前帧允许的计算量；未完成返回 `None`，完成返回 `AssemblyPlan` |
| `done` | 搜索已经成功或失败结束 |
| `search_nodes` | 已深入节点数，用于状态栏进度诊断 |
| `result` | 完成后的成功或失败规划 |
| `cancel()` | 模式切换、进入CAL或重新开始SAVE时丢弃旧任务 |

同步 `solve_unknown_layout()` 保留，供PC测试和非主循环调用使用；它只是连续消费同一增量核心直至结束，避免维护两套算法。

## 4. 搜索停止规则

搜索同时受三层限制：单帧时间预算、单帧工作单元预算和总节点预算。总节点预算防止无解输入无限搜索；单帧双预算保证某个设备计时误差或候选数量异常时仍能尽快让出控制权。

检测到纹理时，首个合法矩形不立即结束，而是记录当时节点数，再搜索有限的附加节点以比较接缝连续性。达到附加节点数后返回当前最佳结果。该规则直接消除“已有结果仍跑满12000节点”，同时保留有限纹理择优能力。

## 5. UNKNOWN数据流

`AssemblyRuntime`继续负责3帧稳定门和结果缓存，但新增“空闲、求解中、已完成”状态。第3个稳定帧只创建任务并推进一个时间片；后续每帧继续推进。任务完成后缓存规划，碎片移动前持续复用，不重复搜索。

状态栏依次显示 `STABLE 1/3`、`STABLE 2/3`、`SOLVING N=<节点数>`、`PLAN OK N=4`或具体失败原因。求解期间仍使用当前相机帧绘制识别轮廓。

## 6. KNOWN SAVE数据流

点击SAVE时先筛选四个完整上半区碎片并复制当前毫米几何，创建 `KnownRegistrationJob`。按钮回调不执行完整搜索，也不写文件。正常循环逐帧推进任务，并显示 `SAVE SOLVING N=<节点数>`。

增量未知求解完成后，任务复用原有逻辑生成精确100×60mm的K1～K4模板和KNOWN规划。只有两者都成功才调用模板原子保存并写入 `AssemblyRuntime` 缓存；失败时保留旧模板。模式切换或进入CAL会取消尚未完成的SAVE任务。

## 7. 测试与发布

测试先证明复杂带纹理四片不能在一个极小工作单元内同步完成，再验证多次推进后得到合法结果。分别覆盖UNKNOWN第3稳定帧和KNOWN SAVE启动路径、模式切换取消、失败状态、首解后有限优化、同步接口兼容以及模板成功后才写入。

最终运行定向pytest、全量pytest、`compileall`、A版平铺ZIP导入和稳定版/B版哈希边界检查。实机验收重点是两条原冻结路径的画面与触摸持续响应，以及下半区最终目标正常出现。
