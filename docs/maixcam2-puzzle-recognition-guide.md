# MaixCAM2 拼图识别程序说明与操作手册

> 本文保留原稳定版固定矩形ROI的说明。自动黑纸四角、四边形掩膜A版、透视展开B版以及新的 `ROI/MASK/RESULT/ADV/CAL` 界面，请以 [自动黑纸ROI A/B操作手册](maixcam2-auto-roi-ab-guide.md) 为准。

## 1. 文档目的

本文说明当前 MaixCAM2 拼图视觉程序具体完成了什么、屏幕按钮如何使用、识别结果如何理解，以及现场运行时需要注意的限制。

当前程序解决的是“看见并描述碎片”，还没有负责计算最终拼图方案，也没有控制龙门架和电机运动。

## 2. 当前硬件与识别对象

| 项目 | 当前条件 |
|---|---|
| 视觉设备 | MaixCAM2 |
| 摄像头安装 | 固定安装 |
| 机械运动范围 | 230mm × 230mm |
| 龙门架 Z 向行程 | 100mm |
| 背景 | 黑色 A4 纸 |
| 被识别物 | 贴有白纸的拼图碎片 |
| 碎片数量 | 1～4 片 |
| 碎片主要边数 | 3～5 条 |
| 当前输入要求 | 碎片之间应互不接触、互不重叠 |

黑色背景与白色贴片有明显亮度差，因此程序使用 OpenCV 阈值分割和轮廓算法，不需要训练 YOLO 模型。

## 3. 程序文件组成

MaixVision 运行工程时，需要保证下面七个 Python 文件都在同一目录中。

| 文件 | 作用 |
|---|---|
| `main.py` | 程序入口，负责相机、显示屏、触摸、模式切换和主循环 |
| `config.py` | 保存分辨率、阈值、面积范围、拟合误差和匹配阈值 |
| `puzzle_vision.py` | 完成黑白分割、轮廓提取、多边形拟合和几何计算 |
| `template_store.py` | 保存、加载并匹配已知碎片模板 |
| `touch_ui.py` | 计算按钮位置、触摸坐标映射和单次点击事件 |
| `settings_store.py` | 校验、保存和加载现场 ROI、阈值及形态学参数 |
| `calibration_ui.py` | 管理调参状态并绘制 `ROI/MASK/RESULT` 三页诊断画面 |

运行已知模式并保存模板后，程序还会生成：

| 文件 | 作用 |
|---|---|
| `known_templates.json` | 保存 `K1～K4` 的形状特征，不保存原始照片 |
| `/root/maixcam2_puzzle/vision_settings.json` | 持久保存现场 ROI、阈值、最小面积和形态学核参数 |

## 4. 程序启动后做了什么

程序运行 `main.py` 后，按下面的顺序初始化：

1. 创建显示屏对象。
2. 以 640×480、BGR888 格式创建摄像头对象。
3. 跳过开始的 30 帧，让曝光和画面先稳定。
4. 创建触摸屏对象、正常界面按钮和调参界面按钮。
5. 从 `/root/maixcam2_puzzle/vision_settings.json` 加载现场参数；文件不存在时使用默认整帧 ROI。
6. 尝试从 `known_templates.json` 加载已知碎片模板。
7. 默认进入 `UNKNOWN` 未知碎片模式和正常识别界面。
8. 循环读取相机、按当前固定 ROI 识别碎片、处理触摸并显示结果，直到应用退出。

主循环的数据流如下：

```text
MaixCAM2 相机画面
        |
        v
转换为 OpenCV BGR 图像
        |
        v
按现场参数截取固定黑纸 ROI
        |
        v
灰度化 -> 高斯滤波 -> 黑白阈值分割
        |
        v
开运算去白色小噪点 -> 闭运算填白纸小孔洞
        |
        v
提取外轮廓 -> 面积过滤 -> 最多保留 4 个轮廓
        |
        v
拟合 3～5 边多边形并计算中心、角度、边长、内角
        |
        +-----------------------------+
        |                             |
        v                             v
UNKNOWN：按位置编号 U1～U4      KNOWN：匹配模板 K1～K4
        |                             |
        +--------------+--------------+
                       v
             绘制轮廓、顶点、中心和状态
                       |
                       +---- CAL：ROI/MASK/RESULT诊断与参数保存
                       |
                       v
                 显示到触摸屏
```

## 5. 单帧识别算法

### 5.1 黑白分割

程序先把彩色图像转换为灰度图，再使用 5×5 高斯滤波降低噪声。

默认配置 `fixed_threshold=None`，表示使用 Otsu 自动阈值。程序会根据当前画面自动计算一个灰度分界值：

- 比阈值亮的白色贴片变成白色前景；
- 比阈值暗的黑色 A4 背景变成黑色背景。

分割后执行：

| 操作 | 当前尺寸 | 作用 |
|---|---:|---|
| 开运算 | 3×3 | 去除小白点、反光点和纸屑噪声 |
| 闭运算 | 5×5 | 填补白纸内部的小黑孔和细小断裂 |

### 5.2 轮廓筛选

程序只提取最外层轮廓，并根据 ROI 面积进行过滤：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `min_area_ratio` | 0.002 | 小于画面面积 0.2% 的轮廓被当作噪声 |
| `max_area_ratio` | 0.60 | 大于画面面积 60% 的轮廓被排除 |
| `max_pieces` | 4 | 按面积从大到小最多保留 4 个轮廓 |

需要注意：如果真实碎片之外还有面积很大的白色干扰物，它可能占用四个轮廓名额之一。

### 5.3 几何信息提取

每个有效轮廓会计算下面的信息：

| 数据 | 用途 |
|---|---|
| `vertices` | 拟合后的多边形顶点坐标 |
| `vertex_count` | 主要顶点数量，目标范围为 3～5 |
| `center` | 轮廓的图像矩中心，可作为后续吸取点参考 |
| `angle_deg` | 最小外接矩形方向角，范围归一化到 -90°～90° |
| `area` | 轮廓像素面积 |
| `perimeter` | 轮廓像素周长 |
| `edge_lengths` | 相邻顶点之间的像素边长 |
| `interior_angles` | 各顶点对应的内角 |
| `complete` | 轮廓是否远离 ROI 边界、是否可认为完整 |

当前 `border_margin_px=2`。轮廓距离 ROI 任意边界不超过 2 像素时，会被标记为不完整轮廓。

这些坐标和长度目前都是像素单位，还没有转换成龙门架使用的毫米坐标。

## 6. 正常界面的四个屏幕按钮

### 6.1 `UNKNOWN`：未知碎片模式

这是程序启动后的默认模式。

点击 `UNKNOWN` 后，程序不会判断碎片属于哪一个预存形状，而是根据碎片中心位置编号：

1. 先从上到下分行；
2. 同一行再从左到右排序；
3. 依次标记为 `U1`、`U2`、`U3`、`U4`。

| 项目 | 说明 |
|---|---|
| 是否需要提前保存模板 | 不需要 |
| 显示编号 | `U1～U4` |
| 适合场景 | 第一次调试、任意新碎片、只需要轮廓和几何信息时 |
| 按钮状态 | 选中后按钮显示绿色 |

编号取决于碎片在画面中的位置。碎片移动到另一行或左右顺序改变后，`U1～U4` 也可能变化，它不是永久身份编号。

### 6.2 `KNOWN`：已知碎片模式

点击 `KNOWN` 后，程序把当前碎片与 `known_templates.json` 中保存的模板进行匹配。

匹配使用以下形状特征：

| 特征 | 说明 |
|---|---|
| 顶点数 | 三角形、四边形、五边形之间会产生明显差异 |
| 归一化边长 | 使用各边占总边长的比例，降低远近和尺寸变化影响 |
| 归一化内角 | 比较各顶点角度关系 |
| Hu 矩 | 描述整体轮廓形状，对平移、缩放和旋转较稳定 |
| 紧致度 | 使用面积与周长平方的比值补充区分形状 |

程序会在最多四片碎片之间执行一对一全局匹配，避免两片观测碎片同时被标成同一个模板。

| 项目 | 说明 |
|---|---|
| 是否需要提前保存模板 | 需要 |
| 匹配成功显示 | `K1～K4` |
| 匹配分数过大 | 显示 `UNKNOWN` |
| 没有模板文件 | 状态栏显示 `NO TEMPLATE` |
| 当前接受阈值 | `known_match_threshold=1.20` |

匹配距离越小，形状越接近。把 `known_match_threshold` 调小会更严格，但也更容易把正确碎片拒识为 `UNKNOWN`；调大则更宽松，但可能误匹配。

### 6.3 `SAVE`：保存已知碎片模板

`SAVE` 只在 `KNOWN` 模式下有效。在 `UNKNOWN` 模式中，它会显示为较暗的禁用状态。

当前界面保存模板的条件是：

1. 已切换到 `KNOWN` 模式；
2. 画面中恰好识别出 4 个轮廓；
3. 4 个轮廓都没有接触 ROI 边界，即全部为完整轮廓。

满足条件并点击 `SAVE` 后，程序会：

1. 为四片碎片计算形状描述子；
2. 按顶点数、紧致度和边长比例进行稳定排序；
3. 将排序后的模板依次命名为 `K1～K4`；
4. 写入 `known_templates.json`；
5. 状态栏显示 `4 TEMPLATES SAVED`。

以下几点需要特别注意：

- `K1～K4` 是按形状特征排序得到的，不是按画面从左到右编号。
- 再次点击 `SAVE` 会用当前四片模板覆盖原来的模板，不是追加模板。
- 保存时四片碎片必须互相分开，否则接触的白色区域会被识别成一个合并轮廓。
- 当前模板文件保存在 `main.py` 同级目录。MaixVision 使用 `/tmp/maixpy_run` 临时目录运行时，模板能否跨重启保留尚未经过实机验证。

### 6.4 `CAL`：进入或退出现场调参

正常界面点击右上角 `CAL` 后进入现场调参界面；再次点击同一位置的 `CAL` 返回正常界面。这个切换不会改变当前 `KNOWN/UNKNOWN` 识别模式。

进入 CAL 时，程序复制当前已保存参数作为工作副本：

- 在 CAL 内调整参数只修改工作副本；
- 未保存就退出 CAL 时，本次修改全部丢弃；
- 只有状态达到 `GOOD 4/4` 时，CAL 底部的 `SAVE` 才可点击；
- CAL 中的 `SAVE` 保存视觉参数，正常界面的 `SAVE` 保存四片已知模板，两者用途不同。

## 7. 触摸按钮的响应方式

程序在手指松开时才生成一次点击事件，而不是在按住期间重复触发。

相机图像以 `FIT_CONTAIN` 方式完整显示到屏幕。如果图像两侧或上下出现黑边，程序会把屏幕触摸坐标反算到相机图像坐标；点击显示黑边不会误触按钮。

按钮颜色含义：

| 显示状态 | 含义 |
|---|---|
| 绿色 | 当前选中的模式 |
| 灰色 | 可以点击但当前未选中 |
| 深色 | 当前不可用，例如 UNKNOWN 模式下的 SAVE |

调参界面的顶部按钮如下：

| 按钮 | 作用 | 正确画面特征 |
|---|---|---|
| `ROI` | 查看原图并调整固定 ROI 四边 | 黄色边界包住黑纸有效区，不包含亮地面 |
| `MASK` | 查看算法实际使用的黑白二值图 | 四片白色区域彼此独立，黑纸区域保持黑色 |
| `RESULT` | 查看每类轮廓的过滤原因 | 目标碎片为绿色，不出现多余橙/红/紫轮廓 |
| `CAL` | 退出调参并返回正常界面 | 不改变进入前的 KNOWN/UNKNOWN 模式 |

底部按钮从左到右为：

| 按钮 | 作用 |
|---|---|
| `ITEM:<名称>` | 循环选择当前 ROI 边或分割参数 |
| `-` | 按当前步长减小所选参数 |
| 中间数值 | 显示当前值；选择 `TH` 时点击可切换 `AUTO` 与固定阈值 |
| `+` | 按当前步长增大所选参数 |
| `STEP:1/5/10` | 循环切换单次调节步长 |
| `SAVE` | 仅在 `GOOD 4/4` 时保存参数到设备持久目录 |

## 8. 画面标记含义

| 画面元素 | 含义 |
|---|---|
| 青色矩形 | 当前 ROI 工作区边界 |
| 绿色轮廓 | 没有接触 ROI 边界的完整轮廓 |
| 橙色轮廓 | 接触 ROI 边界的不完整轮廓 |
| 红色圆点 | 多边形拟合后的主要顶点 |
| 黄色十字 | 轮廓中心 |
| 黄色文字 | 碎片编号、顶点数和方向角 |

碎片旁的文字示例：

```text
U1 V4 15.0deg
```

| 字段 | 含义 |
|---|---|
| `U1` | 未知模式下的第 1 片碎片 |
| `V4` | 该轮廓拟合出了 4 个主要顶点 |
| `15.0deg` | 当前方向角约为 15° |

## 9. 底部状态栏

状态栏示例：

```text
UNKNOWN N=2 EDGE=1 TH=134 READY
```

| 字段 | 含义 |
|---|---|
| `UNKNOWN` | 当前处于未知碎片模式 |
| `N=2` | 当前完整轮廓数量为 2 |
| `EDGE=1` | 当前有 1 个轮廓接触 ROI 边界 |
| `TH=134` | 当前黑白分割阈值为 134 |
| `READY` | 当前状态信息 |

常见状态信息如下：

| 状态文字 | 含义与处理方法 |
|---|---|
| `READY` | 程序已进入主循环 |
| `UNKNOWN MODE` | 已切换到未知碎片模式 |
| `KNOWN MODE` | 已切换到已知碎片模式 |
| `NO TEMPLATE` | 当前没有已知模板，先按要求保存四片模板 |
| `4 TEMPLATES SAVED` | 四个模板已经写入文件 |
| `SAVE NEEDS 4 COMPLETE` | 保存条件不满足，需要恰好四个完整轮廓 |
| `TEMPLATE ERROR <类型>` | 模板文件损坏、版本不兼容或读取失败 |
| `SAVE ERROR <类型>` | 模板文件写入或替换失败 |
| `VISION ERROR <类型>` | 当前帧识别发生异常，程序会继续处理下一帧 |

## 10. 推荐操作流程

### 10.1 第一次固定 ROI 和校准分割

1. 固定相机和黑色 A4 纸，之后不要再改变两者相对位置。
2. 将 4 片白色碎片互相分开，并放到计划保留的 210mm × 230mm 有效区域内。
3. 点击 `CAL`，在 `ROI` 页依次选择四条边，裁掉亮地面和长边上下各约 33mm 的无效区。
4. 进入 `MASK`，确认只有 4 片碎片独立显示为白色；若不正确，一次只调整 `TH`、`MIN`、`OPEN` 或 `CLOSE` 中的一项。
5. 进入 `RESULT`，确认 4 片目标轮廓均为绿色，状态为 `GOOD 4/4`。
6. 点击 CAL 底部 `SAVE`，看到 `SETTINGS SAVED` 后，再点击右上角 `CAL` 返回正常界面。

### 10.2 验证摄像头和轮廓

1. 把 1～4 片白色贴片互相分开摆在黑色 A4 纸上。
2. 运行 `main.py`，程序默认进入 `UNKNOWN`。
3. 检查碎片是否出现绿色轮廓、红色顶点和黄色中心。
4. 检查状态栏中的 `N` 是否等于实际完整碎片数量。
5. 移动和旋转碎片，观察中心与角度是否同步变化。

### 10.3 建立四片已知模板

1. 将需要记忆的四片碎片全部放入画面。
2. 保证四片互不接触、互不重叠，也不接触画面边界。
3. 等待状态栏显示 `N=4 EDGE=0`。
4. 点击 `KNOWN`。
5. 点击 `SAVE`。
6. 确认状态栏显示 `4 TEMPLATES SAVED`。

### 10.4 使用已知模式识别

1. 保持模板对应的碎片互相分开。
2. 点击 `KNOWN`。
3. 检查碎片旁是否显示 `K1～K4`。
4. 如果显示 `UNKNOWN`，先检查光照、遮挡和轮廓是否完整，再考虑调整匹配阈值。

## 11. 现场可调参数

下面这些参数可直接在 CAL 界面调整并持久保存：

| 参数 | 允许值/步长 | 调大或向内裁剪后的影响 | 调小或向外扩展后的影响 |
|---|---|---|---|
| `LEFT/RIGHT/TOP/BOTTOM` | 1、5、10 像素 | 排除更多亮地面和无效纸面，也可能切掉碎片 | 保留区域更大，也更容易把亮背景带入轮廓层级 |
| `TH` | `AUTO` 或 0～255 | 固定阈值升高后只保留更亮区域 | 固定阈值降低后会带入更多灰色反光和噪声 |
| `MIN` | 每步 0.0001 × STEP | 过滤更多小噪点，也可能漏掉远距离小碎片 | 保留更多小轮廓，也会增加噪声 |
| `OPEN` | 1、3、5、7 | 去白点更强，也会侵蚀小碎片 | 更保留小碎片，也更保留纸屑和反光点 |
| `CLOSE` | 1、3、5、7、9 | 填孔更强，也更容易连接相邻碎片 | 不易连接碎片，白纸内部黑孔可能保留 |

`TH=AUTO` 时，中间数值按钮显示本帧 Otsu 阈值，例如 `AUTO:134`。点击该按钮会锁定为当前固定阈值；再次点击切回自动模式。其余参数的中间按钮只显示值，不执行切换。

CAL 状态栏用于判断参数是否正确：

| 状态 | 含义 | 现场处理 |
|---|---|---|
| `GOOD 4/4` | 恰好 4 个完整有效轮廓，没有背景、边缘或额外轮廓 | 可以保存 |
| `MISS n/4` | 完整碎片少于 4 片或顶点数异常 | 查看 MASK，检查 ROI、TH 和 MIN |
| `NOISE` | 面积过滤前仍存在额外有效候选 | 提高 MIN 或 OPEN，并检查反光 |
| `EDGE` | 目标轮廓接触 ROI 边界 | 扩大对应 ROI 边或把碎片移入有效区 |
| `BACKGROUND` | 出现过大亮轮廓或白色占比异常 | 缩小 ROI 排除亮地面，检查 TH |

`RESULT` 页中绿色表示有效，橙色表示触边，红色表示过小，紫色表示过大。状态栏还会显示 `N`、`EDGE`、`SMALL`、`LARGE`、`TH` 和 `WHITE`，因此可以判断问题发生在分割、面积过滤还是 ROI 边界。

`max_area_ratio`、`gaussian_kernel`、`border_margin_px` 和 `known_match_threshold` 仍由 `maixcam2_app/config.py` 提供默认值，不在现场触摸界面中修改。保存后的现场参数位于 `/root/maixcam2_puzzle/vision_settings.json`。

## 14. MaixVision 运行检查

MaixVision 左侧工程文件树中至少要同时看到下面 7 个 Python 文件：

```text
main.py
config.py
puzzle_vision.py
template_store.py
touch_ui.py
settings_store.py
calibration_ui.py
```

然后运行 `main.py`。如果只上传入口文件，程序会因为找不到其他同级模块而退出。

程序已经同时兼容两种导入方式：

- PC 工程目录中的 `maixcam2_app` 包导入；
- MaixVision `/tmp/maixpy_run` 中的同级文件导入。

工程自带的 `maixcam2_app/dist/maix-diansai_1-v1.0.0.zip` 已包含上述运行模块和 `app.yaml`。无论使用目录还是 ZIP，都要确认 `settings_store.py` 与 `calibration_ui.py` 存在，否则 CAL 功能无法启动。
